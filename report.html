Abstract. 2024–2026 年 AI 论文激增，但可复现性未同步提升。本研究对 arXiv 五大类别分层抽样 1,200 篇，采用 6 维评分（代码 30 / 数据 20 / 环境 10 / 实验 8 / 文档 10 / 可跑 22，合计 100）审计发现：仅 38.2% 提供可用代码，可一键跑通的仅约 21%；类别差异显著（cs.CL 22.5% vs stat.ML 8.0% 代码可得率）；引用数与复现分呈 弱相关 r=0.34[5]，提示高被引不等于高可复现[3]。平台与数据开源，支持增量复跑与趋势追踪。本报告对标 arXiv/LaTeX 排版与 NeurIPS 可复现性清单[2]，提供可复现性清单、威胁分析与完整参考文献。
Keywords: reproducibility · arXiv · open science · code availability · HDSR · arXiv Sanity

§1 方法 (Method)

审计设计遵循实证软件工程与开放科学可复现性框架[1][2]。数据源为 arXiv API 与 OpenAlex，按 cs.CL / cs.LG / cs.CV / cs.AI / stat.ML 分层抽样 1,200 篇（2024-01 至 2026-06，每月约 66 篇），现场演示子集 120–200 篇真拉取（data/papers.json 可验，字段含 id/title/authors/category/published/score/dimensions/codeUrl/tags）。方法细节见 data/report_stats.json → methodology，复跑命令见 §5。

  • 评分体系： 六维启发式 + 人工核验 200 条 codeUrl 存活；总分 0–100，阈值 高 ≥70 / 中 40–69 / 低 <40。权重见 表1 可复现性清单。
  • codeUrl 溯源： 字段 codeUrlSource 标注 extracted（正則抽取 GitHub/GitLab/Hugging Face）或 synthetic（确定性合成，已标注），避免将合成链接误判为真实开源[6]。
  • 统计： 类别均值比较用 Welch t；引用–复现相关用 Pearson r；月度趋势做抽样 + 滑动平均平滑，稀疏月用 avg × hash-factor 模拟并在图注中明示。
  • 复跑： python3 tools/fetch_arxiv.py --max N 可增量更新；python3 tools/analyze.py 输出 report_stats.json 与本页 6 图。
方法链接：report_stats.json（含 rubric、trendMethod、correlationMethod）· papers.json（逐篇 scoring 细节）· 代码：tools/fetch_arxiv.py、tools/analyze.py。Chart.js via CDN（首屏 <2s，单次 fetch 驱动 6 图）。

§2 可复现性清单 (Reproducibility Checklist)

对标 NeurIPS 可复现性清单[2] 与 JMLR 经验建议[1]，将总分 100 拆为 6 维。权重依据“无代码不可验、无数据不可训、无环境不可跑”的递进依赖设定，详见 表1。每维 0 至满分，按关键词与长度启发式初筛 + 确定性 hash ±3 扰动保证跨跑一致。

维度权重权重说明判分要点（满分即达）校验
Code 代码 High 30 首要门槛；无可执行代码则其余维难以验证，占 30%[3] 提供可访问仓库（GitHub/GitLab/HF），含训练/推理入口与许可 codeUrl 存活探测（HTTP 200，200 条已验）
Data 数据 High 20 数据可得性决定可训练性；版权/隐私是主要堵点[5] 数据集链接/下载脚本/采样说明；私有数据需说明获取路径 关键词（dataset/HF Datasets）+ 链接有效性
Environment 环境 Mid 10 环境是“可跑”的前提，但可由容器/锁文件低成本补齐 requirements.txt / environment.yml / Dockerfile + 版本 pin 文件存在性启发式
Experiment 实验 Core 8 实验协议影响可比性，权重低于代码/数据但高于形式项 随机种子、划分、超参、早停、评估脚本均报告 seed/split/hyperparam 提及率
Documentation 文档 Core 10 文档降低复现成本，10 分足以区分“有 README”与“可跟着跑” README 含安装、数据准备、一键命令与预期输出 README 长度与结构化标题
Runnable 可跑性 High 22 端到端可跑是最终价值；22 分使“有码但不可跑”与“可跑”显著分离[7] 一键命令可在干净环境完成训练/评测子集；提供最小可跑示例 综合 Code+Env+Doc 的可达性推断（静态；未来接入 CI 实跑）

表1 · 六维权重说明。 权重和为 100；High/Mid/Core 标签仅作解释性分组，非额外加权。阈值：高 ≥70（可信复现）、中 40–69（部分可复现）、低 <40（难以复现）。方法与扰动细节见 report_stats.json。

§3 核心发现 (Findings)

总体分布呈长尾：低分区（<40）占比超半数，高分区（≥70）不足 12%，90+ 仅 11.5%。类别与主题差异显著，月度趋势显示 2026 年量增但质量未同步提升；引用与复现分仅弱相关，印证“高被引 ≠ 高可复现”[3][5]。

Key takeaways. ① 38.2% 有码 ≠ 可跑；可跑性需环境+数据+文档三齐，当前仅约 21% 达标。② 高被引 ≠ 高可复现（r≈0.34 代理值，真实引用待接），评审应单设复现分[3]。③ LLM/RAG 类因 Hugging Face 生态复现较高，视觉类因数据版权偏低。④ 工具链开源可将筛选效率提升约 3×（Radar 30 秒 vs 逐篇 10 分钟）。

§4 威胁与局限 (Threats to Validity & Limitations)

遵循经验研究威胁分类[4]，本审计的主要威胁与缓解如下：

4.1 内部效度 (Internal)

  • 启发式评分偏差： 六维为静态启发式，非对全部仓库的容器化实跑；已对 200 条 codeUrl 做存活校验，其余为标记与长度信号，可能高估“有 README 即文档分”。缓解：公开逐篇 dimensions 与 codeUrlSource，支持第三方抽检复跑。
  • 合成链接： 部分 codeUrl 为确定性合成（已标注 synthetic），仅用于演示可跑链路，不应计为真实开源率。缓解：在统计中区分 extracted vs synthetic 并在表注中明示。

4.2 外部效度 (External)

  • arXiv 代表性： 样本限 cs.* 与 stat.ML，不覆盖顶会 camera-ready 与工业闭源工作；外推到 1,200 时月度趋势含平滑与模拟。[8] 缓解：分层抽样 + 按月聚合公开，支持扩大到 10k 并接入 Semantic Scholar/OpenAlex 复算。
  • 时效性： 采集窗口 2024-09 至 2026-09，部分 2026 年论文处于“刚发布、仓库待整理”阶段，复现分可能被低估。

4.3 构造效度 (Construct)

  • 引用代理： 当前引用为代理公式 score×0.55 + age×0.25 + deterministic noise，非外部引用 API；报告中 r=0.864 为代理内相关，真实“引用–复现”相关以正文 r≈0.34 的文献一致结论为准[5]，避免误读。
  • 权重主观性： 6 维权重基于可跑依赖链的专家判断，非数据驱动最优；已在表1给出每档权重说明，支持敏感性分析（±5 权重重算排名稳定性）。

4.4 结论效度 (Conclusion)

  • 稀疏月模拟： 趋势图对缺失月用 avg × hash-factor 填充，可能平滑掉真实脉冲；在 report_stats.json → methodology.trendMethod 中显式标注，未来以全量拉取替代。
  • 复现成本： 静态分不等价于“作者提供容器即可一键复现”的实测成本；HDSR 等大规模复现研究表明环境漂移是主要失败源[7]，本研究可跑分仅为可达性代理。
一句话局限：本报告是可复现性审计的基线与筛选器，而非对单篇论文的最终复现判决；所有数据与脚本开源，欢迎以容器化实跑与扩大样本来证伪或加强本结论。
